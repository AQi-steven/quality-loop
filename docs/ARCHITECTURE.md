## 2. 前端设计

- **无构建 vanilla JS**：零工具链，改完即部署；代价是模块间靠全局命名空间通信（App / Pages / UI / API）
- **hash 路由**：`#/home`、`#/work`、`#/work/memo` 等；子 tab 必须各有独立 hash，否则同页互切不触发 hashchange
- **权限双真相源**：前端 deriveCaps() 与后端 rbac.js 保持一致，写操作后端再校验
- **版本戳缓存策略**：`index.html` 所有 `?v=YYYYMMDDx` 必须同步升，否则用户拿旧 JS
- **PWA**：manifest + Service Worker（零缓存透传，保证部署即时生效且不白屏）

## 3. 后端设计

- **单体 Express**，路由按业务域分文件（announcements / qualityDissem / pdca / memos / qa / flowers / readAcks / exam / admin / comments / serverchan）
- **RBAC 模型**：role（dean/chief/section_leader/designer/leader）+ extra_roles + division（专业室）+ 特殊账号体系：
  - 游客（is_guest）：免密只读，按角色派生"视野"但零写能力
  - 可考试游客（can_exam）：额外放行 3 个考试写接口
- **幂等迁移**：schema.js 所有 ALTER/CREATE 全部 try-catch 包裹，重复执行安全
- **FTS5 trigram**：中文子串检索；≥3 字 MATCH+bm25+snippet，1~2 字 LIKE 兜底；整句零命中时 2-gram IDF 相关度兜底

## 4. 关键数据流

### 4.1 已阅追踪（应阅池）
```
内容发布 → 动态计算应阅池（按 division/role，作者本人豁免）
        → read_acks 记录已阅 → N/M 完成率 → 未阅站内信提醒
```

### 4.2 小红花激励
```
宣贯发布（3朵）/室主任级（1朵）· PDCA 非院选（2朵）/院选（3朵）
        → awardFlower() 以 (kind, ref_id) 应用层幂等 → 月度榜单
```

### 4.3 库问答 AI
```
用户提问 → FTS 检索（0命中则 IDF 兜底）→ top 资料片段
        → LLM 模型链（主模型失败自动切下一个）→ 200 响应
        → 全挂则优雅降级：200 + ok:false + 兜底资料（不报错不白屏）
```

### 4.4 IMA 知识库同步（可选）
```
公告/宣贯/人人讲发布 → 文字生成 Word + 原附件
        → IMA OpenAPI（create_media → COS PUT → add_knowledge）
        → 失败重试 + 每日自检 + 20 天自动重绑 + 微信告警
```

## 5. 运维体系

| 机制 | 频率 | 说明 |
|---|---|---|
| DB 增量备份 | 15 min | VACUUM INTO，滚动保留 14 天 |
| 整包快照 | 周日 03:07 | 保留 6 份 |
| IMA 自检 | 每日 04:37 | 失效即微信告警 |
| IMA key 提醒 | 每日 08:37 | key ≥25 天每日催换 |
| IMA 自动重绑 | 每 20 天 | 绑定态失效自动恢复 |
| 月度结算 | 每月 1 日 | settleMonth.js |

## 6. 已知技术债（开源版如实列出）

1. 前端全局命名空间耦合（App/Pages/UI/API），无模块化
2. 超管判断硬编码用户名（全局搜 `superadmin` 可定位，建议改配置化）
3. 测试以冒烟脚本为主，无单元测试覆盖
4. 单服务器单库，无读写分离/异地容灾（1GB 内存下的 deliberate 选择）
